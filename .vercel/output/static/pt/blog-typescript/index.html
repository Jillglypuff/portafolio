Querido Diário, TypeScript Não Me Tornou Mais Rápida 🌸

Diário de desenvolvimento da Jill

Quando ouvi falar do TypeScript pela primeira vez... meu primeiro pensamento foi:

"Por que eu adicionaria tipos ao JavaScript?"

O JavaScript já funcionava.

Eu podia construir aplicações. Implantá-las. Lançar recursos.

Adicionar tipos parecia adicionar trabalho extra.

Depois comecei a trabalhar em projetos maiores.

Foi aí que o TypeScript finalmente fez sentido.

Minha primeira suposição errada

Pensei que o TypeScript fosse outra linguagem de programação. Não é.

O TypeScript é JavaScript... com superpoderes.

Ele adiciona tipagem estática, melhores ferramentas e validação em tempo de compilação.

O navegador nunca vê o TypeScript. Com o tempo, tudo se torna JavaScript.

Bugs são mais baratos antes de existirem

Uma das maiores vantagens do TypeScript não é escrever código. É evitar código defeituoso.

Imagine uma função simples para calcular totais. Se alguém passar um texto em vez de um número, o JavaScript falha em tempo de execução.

Com o TypeScript, seu editor destaca o erro imediatamente — muitas vezes antes mesmo de você salvar o arquivo.

Aviso de incompatibilidade de tipo no IDE:

function calculateTotal(price: number, tax: number) {
    return price + tax;
}

// ❌ Type checking error in editor:
calculateTotal("100", 13);
//             ~~~~~
// Error: Argument of type 'string' is not assignable 
// to parameter of type 'number'.

Tipos são documentação

Uma coisa que eu não esperava era o quão mais fácil se torna ler o código.

Quando o parâmetro de uma função é tipado com uma interface, você sabe instantaneamente quais campos são esperados sem ler a implementação.

O JavaScript deixa você adivinhando o que 'data' contém. O TypeScript documenta automaticamente.

Interfaces se tornaram meu recurso favorito

Um conceito que mudou completamente a forma como organizo projetos foram as interfaces.

Em vez de lembrar das estruturas dos objetos, eu as defino uma vez. Agora todas as partes da aplicação concordam em como um Usuário se parece. Frontend, Backend, APIs... todos falam a mesma língua.

interface User {
    id: number;
    name: string;
    email: string;
}

Genéricos pareciam assustadores...

...até que deixaram de ser.

A primeira vez que vi variáveis de tipo genérico (<T>), parecia extremamente complexo. Meses depois, os Genéricos se tornaram um dos meus recursos favoritos.

Em vez de escrever várias funções, uma única função pode trabalhar com segurança com diferentes tipos de dados preservando a informação do tipo. Isso é incrivelmente poderoso.

function identity<T>(value: T): T {
    return value;
}

A inferência de tipos é subestimada

Uma coisa que aprecio no TypeScript é que ele não te obriga a tipar tudo.

Muitas vezes, ele já sabe. Se você declara uma string, ele infere o tipo automaticamente. O compilador faz muito do trabalho por você.

const name = "Jill"; // Infers name: string

Refatorar torna-se menos assustador

Uma coisa que notei depois de usar o TypeScript por um tempo... fiquei com menos medo de mudar o código.

Renomeie uma propriedade, mova uma função ou divida um módulo, e o compilador aponta tudo o que precisa ser atualizado. É como ter outro desenvolvedor revisando meu trabalho em tempo real.

TypeScript não é apenas sobre tipos

Alguns dos meus recursos favoritos não têm nada a ver com tipagem. Ferramentas boas tornam o desenvolvimento muito mais agradável:

  • ✔Melhor IntelliSense
  • ✔Autocompletar mais inteligente
  • ✔Refatoração mais segura
  • ✔Melhor navegação
  • ✔Detecção precoce de erros

Onde o TypeScript realmente brilha

Projetos pequenos? O JavaScript costuma ser suficiente.

Aplicações grandes? É aí que o TypeScript começa a se pagar.

Com centenas de arquivos, vários desenvolvedores, componentes compartilhados e APIs reutilizáveis, a tipagem estática torna-se menos sobre conveniência e mais sobre manutenibilidade.

Conclusão técnica 🌸

Alguns conceitos de TypeScript que todo desenvolvedor deveria aprender:

  • ✦Tipos Primitivos
  • ✦Interfaces
  • ✦Aliases de Tipo
  • ✦Enums
  • ✦Genéricos
  • ✦Tipos Utilitários
  • ✦Tipos de União
  • ✦Inferência de Tipos
  • ✦Propriedades Opcionais
  • ✦Estreitamento (Narrowing)

Aprender esses conceitos gradualmente é muito mais fácil do que tentar aprender tudo de uma vez.

Nota pessoal 🌷

Não acho que o TypeScript torne alguém um desenvolvedor melhor. Boa arquitetura, bons nomes e boa comunicação ainda importam.

Mas o TypeScript remove a incerteza. Em vez de adivinhar o que uma variável deve conter, o código te diz.

Em vez de encontrar bugs em produção, você os encontra enquanto escreve o recurso. E honestamente... durmo um pouco melhor por causa disso.

Coisas Que Quero Lembrar 💖

  • ✦TypeScript é JavaScript, não um substituto.
  • ✦Tipos são documentação.
  • ✦Interfaces melhoram a comunicação em todo o projeto.
  • ✦Genéricos são menos assustadores do que parecem.
  • ✦Ferramentas boas tornam o desenvolvimento mais agradável.
  • ✦Pegar bugs durante o desenvolvimento é sempre mais barato do que encontrá-los na produção.
