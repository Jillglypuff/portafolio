Querido Diário, Code for the People 🌸

Diário de desenvolvimento da Jill

Às vezes passamos tanto tempo aprendendo frameworks... que esquecemos de fazer uma pergunta muito maior.

Quem está construindo a internet?

Ou talvez uma ainda melhor:

A internet deveria pertencer a quem?

Essas foram as perguntas que não parava de pensar depois de assistir Code for the People.

Eu esperava um documentário sobre WordPress.

Em vez disso, encontrei uma história sobre comunidade, colaboração e por que o Open Source continua importando.

Minha primeira confusão

Por muito tempo, achei que Open Source simplesmente significava:

"O código é público."

Tecnicamente... isso é verdade.

Mas isso é só o começo.

Open Source não é apenas sobre publicar código fonte.

É sobre permitir que milhares de pessoas ao redor do mundo melhorem algo juntas.

Alguém corrige um bug.

Alguém traduz documentação.

Alguém reporta um problema.

Alguém melhora a acessibilidade.

Alguém revisa um pull request.

Alguém escreve testes.

Pouco a pouco... o software evolui.

A Web Aberta

Uma das ideias que mais ressoou em mim durante o documental foi a importância de manter a web aberta.

Uma web aberta significa que desenvolvedores podem construir.

Criadores podem publicar.

Negócios podem crescer.

Comunidades podem colaborar.

Sem depender inteiramente de uma única plataforma.

A internet se tornou o que é hoje porque inúmeras tecnologias foram construídas abertamente.

Não apenas WordPress.

Mas também projetos como:

Linux. PHP. Git. Node.js. React. Vue. MySQL.

Todos os dias construímos sobre o trabalho que alguém decidiu compartilhar.

Às vezes esquecemos o quão extraordinário isso realmente é.

Notas Técnicas ✨

Coisas que aprendi enquanto assistia e pesquisava.

1. Open Source de uma perspectiva técnica

Desenvolvedores podem:

Aprender como softwares reais são construídos
Reportar problemas
Enviar Pull Requests
Melhorar documentação
Construir plugins ou extensões
Ajudar a revisar código
Compartilhar ideias com a comunidade

Open Source não significa "software gratuito." Significa que o código fonte está disponível sob uma licença que permite aos desenvolvedores inspecionar, modificar e contribuir com ele. Isso cria algo muito maior que uma base de código. Cria um ecossistema.

2. WordPress é muito mais que um CMS

Uma visão simplificada se parece com isso:

Navegador
↓
Tema
↓
Plugins
↓
WordPress Core
↓
PHP
↓
MySQL

Cada camada tem sua própria responsabilidade. O WordPress Core fornece a base. Temas controlam a apresentação. Plugins estendem a funcionalidade. PHP lida com a lógica da aplicação. MySQL armazena os dados. Por causa dessa arquitetura, desenvolvedores podem construir quase qualquer coisa sem modificar o Core.

3. Um recurso que mudou tudo: Hooks

Ações permitem que código personalizado execute quando eventos específicos ocorrem:

add_action('init', function () {
    // Executa quando o WordPress inicializa
});

Filtros funcionam de forma semelhante:

add_filter('the_title', function ($title) {
    return strtoupper($title);
});

Em vez de alterar o código fonte original... você personaliza o comportamento através de pontos de extensão. É uma das razões pelas quais o WordPress permaneceu tão flexível por tantos anos.

A comunidade também faz parte da arquitetura

Uma coisa que o documental me lembrou é que comunidades são tão importantes quanto frameworks.

Tive a oportunidade de comparecer a alguns eventos organizados pela comunidade WordPress Costa Rica.

Tanto a empresa onde trabalho quanto o estúdio de software do qual faço parte são equipes relativamente pequenas.

Por isso, conhecer desenvolvedores de diferentes empresas, indústrias e contextos foi incrivelmente valioso.

Perspectivas diferentes.

Desafios diferentes.

Formas diferentes de abordar o mesmo problema.

Às vezes você não sai de um meetup com um novo framework para aprender.

Às vezes você sai com uma forma completamente diferente de pensar.

E acho que isso é ainda melhor.

Uma frase ficou comigo ✨

Uma mensagem aparece ao longo do documental de diferentes formas.

A internet pertence a todos.

Isso não significa que todos escrevam código.

Mas todos se beneficiam quando o conhecimento é compartilhado.

Quando o software é transparente.

Quando comunidades colaboram.

Quando desenvolvedores se ajudam uns aos outros em vez de competir o tempo todo.

Essa ideia pareceu surpreendentemente refrescante.

Nota pessoal 🌷

Assistir Code for the People me lembrou que uma das coisas que mais gosto na tecnologia não é uma linguagem ou framework específico.

São as pessoas por trás deles.

Aprendi muito com meus colegas de equipe.

Mas participar de eventos comunitários também me mostrou quanto há para descobrir fora dos projetos nos quais trabalho todos os dias.

Cada conversa.

Cada meetup.

Cada experiência compartilhada.

Adiciona outra peça à forma como penso como desenvolvedora.

E honestamente... espero nunca parar de aprender assim.

Resumo técnico 🌸

O sucesso do Open Source não é apenas sobre qualidade de código.

Também é sobre:

Documentação. Comunidade. Revisões de código. Acessibilidade. Controle de versão. Manutenção de longo prazo. Conhecimento compartilhado.

Software não é sustentado por repositórios.

É sustentado por pessoas.

Coisas Que Quero Lembrar 💖

  • ✦Open Source é sobre pessoas tanto quanto sobre código
  • ✦Toda contribuição importa, não importa quão pequena seja
  • ✦Grandes comunidades criam softwares excelentes
  • ✦WordPress é muito mais que um CMS
  • ✦Aprendizado não acontece apenas através de documentação—também acontece através de conversas
