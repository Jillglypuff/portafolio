Querido Diário, Finalmente Entendi SaaS, PaaS e IaaS 🌸

Diário de desenvolvimento da Jill

Achei que computação em nuvem era apenas "o computador de outra pessoa".

Acontece que é realmente sobre decidir o que você quer gerenciar—e o que não.

Computação em nuvem costumava soar como um daqueles assuntos que todos entendiam casualmente, exceto eu.

As pessoas diziam coisas como:

"Vamos implantar na nuvem."

Ou: "Vamos usar um PaaS."

Todos acenaram.

Eu também acenei.

Eu entendia completamente a diferença?

Absolutamente não.

Minha primeira confusão

Na minha cabeça, serviços em nuvem se pareciam com isso:

Escrever código → Implantar → Magia da internet ✨ → Aplicação está online

Parecia simples.

Até que comecei a implantar meus próprios projetos e percebi que alguém, em algum lugar, é responsável por muito mais do que apenas executar a aplicação.

Servidores. Sistemas operacionais. Redes. Segurança. Escalabilidade. Monitoramento. Backups.

E de repente aquelas três siglas começaram a fazer muito mais sentido.

Três camadas, três responsabilidades diferentes

Uma das formas mais fáceis de entender serviços em nuvem é perguntando:

Quem é responsável pelo quê?

Quanto mais responsabilidade o provedor assume, menos infraestrutura você precisa gerenciar.

Notas Técnicas ✨

Coisas que aprendi enquanto pesquisava serviços em nuvem.

1. IaaS — Infraestrutura como Serviço

Responsabilidades típicas:

Você gerencia:
✔ Sistema Operacional
✔ Tempo de execução
✔ Aplicação
✔ Banco de dados
✔ Segurança

O provedor gerencia:
✔ Hardware físico
✔ Redes
✔ Virtualização

Provedores comuns:

Amazon EC2
Microsoft Azure Virtual Machines
Google Compute Engine
DigitalOcean Droplets

IaaS oferece flexibilidade máxima... mas também responsabilidade máxima.

2. PaaS — Plataforma como Serviço

Fluxo de trabalho típico:

Enviar código
↓
A plataforma constrói a aplicação
↓
Implantar
↓
Aplicação está online

Exemplos:

Vercel
Render
Railway
Heroku

Isso é exatamente por que gosto de implantar meu portfólio na Vercel. Não preciso configurar Linux. Não preciso instalar Node. Não preciso me preocupar com servidores web. Simplesmente me concentro em construir a aplicação.

3. SaaS — Software como Serviço

Exemplos:

GitHub
Notion
Figma
Slack
Google Docs
Canva

Este na verdade é o mais fácil. Você não constrói o software. Simplesmente usa. O provedor gerencia tudo. Você só precisa de uma conta.

4. Exemplos reais dos meus próprios projetos

Enquanto construía meu portfólio, meu stack parecia algo assim:

Vue
↓
Vercel (PaaS)
↓
Domínio personalizado

Para projetar interfaces / Para armazenar dados do projeto:

Figma

Supabase

Supabase é interessante porque fornece múltiplos serviços gerenciados, incluindo bancos de dados PostgreSQL, autenticação, armazenamento e APIs. Permite que desenvolvedores se concentrem mais na lógica da aplicação em vez de gerenciar infraestrutura.

Visualizando a diferença

SaaS — Você usa software

↓

PaaS — Você constrói software

↓

IaaS — Você constrói e gerencia infraestrutura

Quanto mais fundo você vai...

mais controle você ganha.

mais responsabilidade você aceita.

Por que isso importa? ✨

Entender esses conceitos muda a forma como você pensa sobre arquitetura.

Em vez de perguntar: "Qual serviço em nuvem devo usar?"

Você começa a perguntar:

Quanto controle eu preciso?

Quanta manutenção eu quero?

Quanto tempo eu quero gastar gerenciando servidores?

Posso deixar outra pessoa cuidar da infraestrutura?

Essas perguntas geralmente importam mais do que a tecnologia em si.

Nota pessoal 🌷

Como ariana, descobrir que outra pessoa poderia gerenciar os servidores para mim foi excelentíssima notícia.

Gosto de construir aplicações.

Não sonho necessariamente em configurar Linux às 2h da manhã.

Talvez algum dia.

Hoje não.

Resumo técnico 🌸

Não existe uma opção "melhor".

Cada modelo resolve problemas diferentes.

SaaS: Usar software sem gerenciar infraestrutura.

PaaS: Desenvolver e implantar aplicações rapidamente.

IaaS: Controle total de infraestrutura e ambientes personalizados.

Escolher entre eles é uma decisão arquitetural, não apenas técnica.

Coisas Que Quero Lembrar 💖

  • ✦Computação em nuvem não é uma coisa só—é uma coleção de modelos de serviço
  • ✦Mais controle geralmente significa mais responsabilidade
  • ✦PaaS me permite focar em construir em vez de manter infraestrutura
  • ✦SaaS alimenta muitas das ferramentas que já uso todos os dias
  • ✦Boa arquitetura começa com entender trade-offs
