Querido Diario, TypeScript No Me Hizo Más Rápida 🌸

El diario de desarrollo de Jill

Cuando escuché hablar de TypeScript por primera vez... mi primer pensamiento fue:

"¿Por qué agregaría tipos a JavaScript?"

JavaScript ya funcionaba.

Podía construir aplicaciones. Desplegarlas. Lanzar características.

Agregar tipos se sentía como agregar trabajo extra.

Luego comencé a trabajar en proyectos más grandes.

Fue entonces cuando TypeScript finalmente tuvo sentido.

Mi primer supuesto incorrecto

Pensé que TypeScript era otro lenguaje de programación. No lo es.

TypeScript es JavaScript... con superpoderes.

Agrega tipado estático, mejores herramientas y validación en tiempo de compilación.

El navegador nunca ve TypeScript. Con el tiempo, todo se convierte en JavaScript.

Los errores son más baratos antes de que existan

Una de las mayores ventajas de TypeScript no es escribir código. Es evitar el código defectuoso.

Imagina una función simple para calcular totales. Si alguien pasa un texto en lugar de un número, JavaScript falla en tiempo de ejecución.

Con TypeScript, tu editor resalta el error de inmediato, a menudo antes de guardar el archivo.

Advertencia de discrepancia de tipo en el IDE:

function calculateTotal(price: number, tax: number) {
    return price + tax;
}

// ❌ Type checking error in editor:
calculateTotal("100", 13);
//             ~~~~~
// Error: Argument of type 'string' is not assignable 
// to parameter of type 'number'.

Los tipos son documentación

Una cosa que no esperaba era cuánto más fácil se vuelve leer el código.

Cuando el parámetro de una función está tipado con una interfaz, sabes al instante qué campos se esperan sin leer la implementación.

JavaScript te deja adivinando qué contiene 'data'. TypeScript lo documenta automáticamente.

Las interfaces se convirtieron en mi característica favorita

Un concepto que cambió por completo cómo organizo los proyectos fueron las interfaces.

En lugar de recordar las estructuras de los objetos, las defino una vez. Ahora todas las partes de la aplicación están de acuerdo en cómo se ve un Usuario. Frontend, Backend, APIs... todos hablan el mismo idioma.

interface User {
    id: number;
    name: string;
    email: string;
}

Los genéricos parecían aterradores...

...hasta que dejaron de serlo.

La primera vez que vi variables de tipo genérico (<T>), parecía extremadamente complejo. Meses después, los Genéricos se convirtieron en una de mis características favoritas.

En lugar de escribir múltiples funciones, una sola función puede trabajar de manera segura con diferentes tipos de datos conservando la información del tipo. Eso es increíblemente potente.

function identity<T>(value: T): T {
    return value;
}

La inferencia de tipos está subestimada

Una cosa que aprecio de TypeScript es que no te obliga a tipar todo.

A menudo, ya lo sabe. Si declaras una cadena de texto, infiere el tipo automáticamente. El compilador hace gran parte del trabajo por ti.

const name = "Jill"; // Infers name: string

Refactorizar se vuelve menos aterrador

Una cosa que noté después de usar TypeScript por un tiempo... me volví menos temerosa de cambiar el código.

Renombra una propiedad, mueve una función o divide un módulo, y el compilador señala todo lo que necesita ser actualizado. Es como tener a otro desarrollador revisando mi trabajo en tiempo real.

TypeScript no es solo sobre tipos

Algunas de mis características favoritas no tienen nada que ver con el tipado. Las buenas herramientas hacen que el desarrollo sea mucho más agradable:

  • ✔Mejor IntelliSense
  • ✔Autocompletado más inteligente
  • ✔Refactorización más segura
  • ✔Mejor navegación
  • ✔Detección temprana de errores

Dónde brilla realmente TypeScript

¿Proyectos pequeños? JavaScript suele ser suficiente.

¿Aplicaciones grandes? Ahí es donde TypeScript comienza a amortizarse.

Con cientos de archivos, múltiples desarrolladores, componentes compartidos y APIs reutilizables, el tipado estático se vuelve menos una conveniencia y más una cuestión de mantenibilidad.

Conclusión técnica 🌸

Algunos conceptos de TypeScript que todo desarrollador debería aprender:

  • ✦Tipos Primitivos
  • ✦Interfaces
  • ✦Alias de Tipo
  • ✦Enums
  • ✦Genéricos
  • ✦Tipos de Utilidad
  • ✦Tipos de Unión
  • ✦Inferencia de Tipos
  • ✦Propiedades Opcionales
  • ✦Estrechamiento (Narrowing)

Aprender estos conceptos gradualmente es mucho más fácil que intentar aprender todo a la vez.

Nota personal 🌷

No creo que TypeScript haga a alguien mejor desarrollador. La buena arquitectura, los buenos nombres y la buena comunicación siguen importando.

Pero TypeScript elimina la incertidumbre. En lugar de adivinar qué debería contener una variable, el código te lo dice.

En lugar de encontrar errores en producción, los encuentras mientras escribes la funcionalidad. Y honestamente... duermo un poco mejor gracias a eso.

Cosas Que Quiero Recordar 💖

  • ✦TypeScript es JavaScript, no un reemplazo.
  • ✦Los tipos son documentación.
  • ✦Las interfaces mejoran la comunicación en todo el proyecto.
  • ✦Los genéricos son menos aterradores de lo que parecen.
  • ✦Las buenas herramientas hacen que el desarrollo sea más agradable.
  • ✦Detectar errores durante el desarrollo siempre es más barato que encontrarlos en producción.
