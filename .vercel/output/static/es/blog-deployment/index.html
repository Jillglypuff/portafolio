Querido Diario, Desplegar Se Sintió Más Aterrador Que Programar 🌸

El diario de desarrollo de Jill

Durante mucho tiempo, pensé que el desarrollo de software terminaba aquí:

Escribe el código. Pruébalo. Listo.

Luego desplegué mi primera aplicación real.

Fue entonces cuando descubrí una verdad incómoda.

El despliegue no es el final del desarrollo.

Es el momento en que tu código se encuentra con el mundo real.

Mi primer supuesto incorrecto

Imaginaba que el despliegue era básicamente esto:

Expectativa
  • 1 git push
  • 2 Production
  • 3 🎉 Feliz
Realidad
  • 1 git push
  • 2 Build Failed
  • 3 Fix Env Vars
  • 4 Build Again
  • 5 Another Error
  • 6 Fix Deps
  • 7 Deploy
  • 8 Production Bug
  • 9 Rollback
  • 10 Coffee ☕

git push → Producción → 🎉 Todo el mundo está feliz

La realidad se veía muy diferente. Parecía que todo tenía que fallar antes de funcionar.

Tu aplicación no corre en tu computadora

Una lección que todo desarrollador aprende eventualmente: "Si funciona en mi máquina..." no significa que funcione en ningún otro lugar.

Producción tiene diferentes requisitos de configuración:

  • 📍Variables de entorno
  • 📍Bases de datos
  • 📍Dominios
  • 📍Claves de API
  • 📍Reglas de red
  • 📍Permisos de archivos
  • 📍Procesos de construcción

La aplicación no cambia. El entorno sí.

Las variables de entorno importan

Escribir secretos directamente en el código puede funcionar durante el desarrollo. Nunca debería llegar a producción.

En lugar de escribir claves de API directamente en el código:
// ❌ Hardcoded secrets (DANGEROUS)
const apiKey = "AIzaSy********";
const dbHost = "12.34.56.78";
Las aplicaciones deberían depender de variables de entorno:
# env variables (SAFE & DYNAMIC)
APP_URL=https://example.com
DB_HOST=localhost
DB_DATABASE=my_database
API_KEY=********

Mantener la configuración fuera del código hace que las aplicaciones sean más seguras y fáciles de mantener.

El despliegue es más que subir archivos

Los despliegues modernos suelen implicar varios pasos. Cada etapa es otra oportunidad para detectar problemas antes que los usuarios.

CI/CD lo cambió todo

Un concepto que cambió por completo mi comprensión del despliegue fue la Integración Continua y el Despliegue Continuo (CI/CD).

En lugar de copiar archivos manualmente a un servidor... el pipeline se encarga de las tareas repetitivas de forma automática. La automatización reduce el error humano.

Y los humanos somos sorprendentemente creativos a la hora de crear problemas de despliegue.

El primer error en producción

Cada desarrollador lo recuerda. Todo se veía perfecto localmente. Producción tenía otros planes.

A veces es una variable de entorno faltante. A veces una migración de base de datos. A veces una configuración de CORS. O una restricción de clave de API olvidada.

Producción tiene una forma de exponer supuestos que no sabías que tenías.

El monitoreo es parte del despliegue

Desplegar no es suficiente. También necesitas saber si todo sigue funcionando.

Lanzar software sin monitoreo es como pilotar un avión sin instrumentos.

Los rollbacks están subestimados

Una lección de la que desearía que más gente hablara: una buena estrategia de despliegue siempre incluye un plan de rollback.

Porque a veces la decisión más segura no es arreglar producción. Es volver a la última versión estable.

Ser capaz de recuperarse rápidamente es tan importante como desplegar rápidamente.

Mis herramientas de despliegue favoritas

A lo largo de diferentes proyectos, he trabajado con plataformas de despliegue como Vercel, Netlify, Google Play Console y servidores web tradicionales para aplicaciones Laravel.

Cada una resuelve un problema diferente. Pero todas tienen algo en común: eventualmente... te enseñarán a respetar producción.

Conclusión técnica 🌸

El despliegue no es una sola acción. Es un proceso de ingeniería.

Un despliegue confiable suele incluir:

  • ✔Control de versiones
  • ✔Gestión de entornos
  • ✔Construcciones automatizadas
  • ✔Pruebas
  • ✔Monitoreo
  • ✔Estrategia de rollback

El objetivo no es simplemente subir el código. Es lanzar software de forma segura.

Nota personal 🌷

Una cosa que he notado a lo largo de mi carrera es que el miedo al despliegue nunca desaparece por completo. Y tal vez eso sea bueno.

Producción afecta a usuarios reales. Negocios reales. Datos reales. Sentir un poco de nervios antes de presionar Desplegar significa que entiendes la responsabilidad detrás de ello.

Con el tiempo, ese miedo se convierte en confianza. No porque los despliegues dejen de fallar, sino porque aprendes a prepararte para ellos.

Cosas Que Quiero Recordar 💖

  • ✦"Funciona en mi máquina" no es una estrategia de despliegue.
  • ✦Las variables de entorno son parte de la aplicación.
  • ✦CI/CD reduce los errores repetitivos.
  • ✦El monitoreo es tan importante como el despliegue.
  • ✦Cada despliegue debería tener un plan de rollback.
