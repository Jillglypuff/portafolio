Dear Diary, I Thought I Was Building a Website 🌸

A developer diary by Jill

At some point I had what felt like a very simple idea.

Build a website.

People browse.

People place orders.

Done.

Very innocent.

Very optimistic.

Very incorrect.

Because the more I worked on it…

the more I realized:

I wasn't building pages.

I was building decisions.

My first wrong assumption

I thought online shopping systems mostly worked like this:

User → Add to cart → Pay → Order complete

Simple.

Then reality arrived.

And suddenly the questions became:

What happens if inventory changes?

What happens if payment succeeds but the order fails?

How do international purchases work?

How do shipping updates happen?

How do users ask for support?

How should promotions behave?

What happens if someone abandons checkout?

And somehow—

one page became an entire ecosystem.

Discovery of the day

Buying something online isn't only buying.

Behind a purchase there are usually:

🛒 product selection

💳 payment processing

📦 shipping coordination

🌎 international logistics

💬 communication

📍 tracking

🔄 status updates

📧 notifications

And suddenly—

I wasn't designing screens.

I was designing flows.

Technical Notes ✨

This project is still in development, but these are some of the technical decisions I've made so far.

1. Laravel became my system layer

Very simplified:

Frontend (Vue)
↓
API
↓
Laravel
↓
Database

Things I'm currently using Laravel for:

- API endpoints
- business rules
- order processing
- payment flow handling
- validations
- service organization

And honestly—the more features I add… the more I appreciate backend organization.

2. Vue became the experience layer

Current mental model:

User
↓
Vue Components
↓
State
↓
API Calls
↓
UI updates

Things I care about here:

🌸 reusable components
🌸 responsive experience
🌸 maintainability
🌸 keeping interfaces simple

Because users shouldn't feel the architecture. Only the experience.

3. I introduced Supabase and accidentally started thinking differently

Current simplified architecture:

Laravel
↓
Supabase
↓
Application Data

Things I started thinking about:

- relationships
- data consistency
- scalability
- status tracking
- future automations

One additional field suddenly becomes ten affected screens. Unexpectedly humbling.

4. Payment gateways taught me trust architecture

The happy path sounds easy:

Checkout
↓
Payment
↓
Success

Actual thinking became more like:

Checkout
↓
Payment Request
↓
Gateway Response
↓
Validation
↓
Order Confirmation
↓
Notifications

Because money has opinions. And systems should respect that.

5. Routes are more complicated than maps

Initial expectation:

origin
+
destination
=
done

Reality:

Location
↓
Coordinates
↓
Distance
↓
Travel estimation
↓
Route generation
↓
Display

And suddenly maps became backend.

The part nobody warned me about

The funny thing is—

every new feature secretly becomes another system.

Support chat.

Promotions.

Notifications.

Shipping.

Gift cards.

Everything connects.

Which means every decision starts affecting something else.

That was the moment this stopped feeling like a website.

Things I want to explore later ✨

There are still features I haven't finished yet.

🌸 automations
↓
🌸 support chat
↓
🌸 AI-generated gift card designs
↓
🌸 notifications
↓
🌸 order tracking
↓
🌸 recommendation systems

And I already know each one deserves its own article.

When it finally clicked ✨

At some point I stopped asking:

"How do I build this page?"

And started asking:

"What happens after the user clicks?"

That question changed everything.

Because products aren't screens.

They're systems.

Personal note 🌸

As an Aries, every week I discover a new feature and immediately think:

"This shouldn't take long."

That statement has not been historically accurate.

The real lesson 💖

I thought I was building a website.

But apparently I was designing:

operations.

flows.

business rules.

customer experience.

And honestly—

that feels much more interesting.

Things I Want To Remember 🌷

  • ✦Systems are bigger than interfaces
  • ✦Payments deserve respect
  • ✦Data changes architecture
  • ✦Good UX includes invisible work
  • ✦Every feature creates responsibilities
