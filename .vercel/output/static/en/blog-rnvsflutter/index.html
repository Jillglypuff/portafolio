Dear Diary, React Native vs Flutter 🌸

A developer diary by Jill

One of the questions I hear the most is:

"Should I learn React Native or Flutter?"

The answer is...

It depends.

And I know that's probably the least satisfying answer possible.

But after working with Expo (React Native) while also exploring Flutter, I realized something.

This isn't a battle.

They're simply different tools designed for different situations.

My first misconception

I used to think the comparison looked like this:

React Native 🆚 Flutter

Winner.

Loser.

Pick one.

Never look back.

The more I learned...

the more I realized that's not how software engineering works.

Frameworks solve problems.

Choosing one should always start with understanding what problem you're trying to solve.

How they actually work

Although both frameworks let you build Android and iOS apps from a single codebase, their architectures are very different.

React Native

React Native uses JavaScript (or TypeScript) to communicate with native components.

Simplified architecture:

React Components
        │
JavaScript / TypeScript
        │
React Native Bridge (or JSI)
        │
Native Platform Components

Instead of drawing every UI element itself, React Native relies on native components. That means buttons are Android/iOS buttons, making navigation feel natural.

Flutter

Flutter takes a completely different approach.

Architecture diagram:

Flutter Widgets
        │
      Dart
        │
 Flutter Engine (Skia)
        │
   Android / iOS

Flutter draws pixels directly using its rendering engine, providing a highly consistent interface across different platforms.

Performance

This is probably the biggest myth.

People often say: "Flutter is faster."

Reality is more nuanced.

Both frameworks can achieve excellent performance.

Flutter has an advantage when building highly animated interfaces because it controls the rendering pipeline.

React Native benefits from using native UI components and has improved significantly with the New Architecture (Fabric, TurboModules and JSI).

In most business applications... users won't notice the difference.

Poor architecture usually hurts performance much more than the framework itself.

Developer Experience

This is where personal preference starts to matter.

React Native

Pros:

  • ✔ JavaScript / TypeScript ecosystem
  • ✔ Easy transition for React developers
  • ✔ Huge npm ecosystem
  • ✔ Expo simplifies development dramatically
  • ✔ Excellent for teams already building React applications

Challenges:

  • ⚠ Native modules sometimes require platform-specific knowledge.
  • ⚠ Dependency compatibility can occasionally become frustrating.

Flutter

Pros:

  • ✔ Consistent UI across platforms
  • ✔ Excellent documentation
  • ✔ Powerful widget system
  • ✔ Beautiful animations
  • ✔ Strong tooling

Challenges:

  • ⚠ Requires learning Dart.
  • ⚠ Smaller ecosystem compared to JavaScript.
  • ⚠ Larger application sizes in some scenarios.

Expo deserves its own section

One thing that completely changed my perception of React Native was discovering Expo.

At first, I assumed React Native required configuring Android Studio, Xcode, Gradle, CocoaPods...

and spending hours fixing environment issues.

Expo abstracts much of that complexity. Some features that stand out:

File-based routing (Expo Router)
↓
OTA (Over-the-Air) Updates
↓
Push Notifications
↓
Camera
↓
Location
↓
Secure Storage
↓
Authentication
↓
EAS Build
↓
Easier deployment

It allows developers to focus more on building features than configuring infrastructure.

A quick comparison

React NativeFlutter
Language: JavaScript / TypeScriptLanguage: Dart
Uses native UI componentsDraws its own UI
Excellent for React teamsExcellent for highly customized interfaces
Massive JavaScript ecosystemStrong Flutter ecosystem
Expo simplifies developmentFlutter includes many tools out of the box

Which one would I choose?

If my project already uses React on the web... I'd probably choose React Native.

Sharing knowledge, components, and even business logic across teams can be a huge advantage.

If I were building an application with highly customized animations, complex UI, or identical interfaces across multiple platforms... Flutter would be incredibly attractive.

Neither choice is objectively better.

Architecture, team experience, deadlines, and product requirements matter much more than internet debates.

Technical takeaway 🌸

Choosing a framework isn't about finding the "best" one. It's about understanding trade-offs.

Ask questions like:

  • ?What language does the team already know?
  • ?Will we share code with a web application?
  • ?How much platform-specific functionality do we need?
  • ?Do we need highly customized UI?
  • ?What's our deployment pipeline?
  • ?Who will maintain the project in two years?

Those answers are usually more valuable than benchmark comparisons.

Personal note 🌷

One of the things I've enjoyed most about mobile development is realizing that frameworks come and go...

but good engineering decisions last much longer.

Every project teaches something different.

Sometimes it's a new API.

Sometimes it's deployment.

Sometimes it's architecture.

And sometimes... it's learning that there isn't always a single right answer.

Things I Want To Remember 💖

  • ✦Every framework has trade-offs.
  • ✦Architecture matters more than popularity.
  • ✦Expo makes React Native much more approachable.
  • ✦Flutter's rendering engine is one of its biggest strengths.
  • ✦Good developers choose tools based on problems—not trends.

Sometimes the hardest part of software development isn't writing code. It's knowing when to throw it away and start over.

— Jill
